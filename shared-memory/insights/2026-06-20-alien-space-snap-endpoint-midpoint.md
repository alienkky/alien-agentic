# 인사이트 — 끝점/중점 스냅: 우선순위는 "선택"이 아니라 "정렬"에서 갈린다

날짜: 2026-06-20 · 슬라이스 4 (ALI-113) · ALIEN SPACE Phase 2

## 한 줄
스냅은 **후보 수집 → 임계 선택 → 우선순위 정렬** 3단으로 쪼개면 순수함수로 테스트되고, UI(인디케이터)·입력감도(터치/펜)는 그 위에 얇게 얹힌다.

## 무엇을
- 후보(`snapCandidates`)는 *렌더가 그리는 변과 동일한 규칙*으로 만든다 — 점 ≥3 닫힌 루프, 아니면 열린 폴리라인. 중점은 그 변 정의에서 자동 도출. 렌더와 스냅이 다른 변 규칙을 쓰면 "보이는 중점과 잡히는 중점이 어긋나는" 버그가 난다.
- 우선순위는 거리 최소화가 아니라 **종류 우선**이다: 임계 내 끝점이 하나라도 있으면 끝점, 없을 때만 중점. 끝점이 더 멀어도 끝점이 이긴다. (CAD 관례 — 끝점이 의미적으로 더 강함)
- 화면거리 임계를 world 로 환산할 때 `pickTolerance` px 를 재사용하되 마우스 환산이 *기존 감도(radius·0.04)* 와 일치하도록 계수(0.01)를 잡아 **회귀 0**. 새 기능이 기존 손맛을 바꾸지 않게.

## 왜 (재사용 가능한 교훈)
- 순수 커널 모듈로 빼면 store/뷰를 안 건드리고 단위테스트가 붙는다 — DoD "스냅 선택 테스트 2건"을 store mock 없이 충족.
- "스코프 크리프 금지"는 **선행 부채를 떠안지 않는 방패**도 된다: e2e 스모크가 툴바 리팩터로 stale 했지만, clean HEAD 동일 실패를 git stash 로 증명하고 본 슬라이스 무관으로 분리 기록 → 게이트 실패의 책임 소재를 명확히.

## 어떻게 적용
- 다음 스냅류(슬라이스 5 면 위 스케치, 교차점 스냅)도 같은 3단 구조 + `resolveSketchSnap` 단일 진입점에 후보만 추가.
- 게이트가 선행 부채로 깨지면 고치기 전에 *clean HEAD 재현*으로 무관함을 먼저 증명한다.
