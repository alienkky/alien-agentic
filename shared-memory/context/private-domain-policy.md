# Private Domain Policy — 가족·심리·연애·건강·법무·미공개 재정 분리 정책

> **공개 문서.** 이 정책 자체는 모든 에이전트가 읽을 수 있다.
> 분리 *대상*은 [shared-memory/_private/](../_private/README.md) 로 격리되며 에이전트의 시야에서 사라진다.
>
> 뿌리: 헌법 §VIII *"가족 시간 신성화"* — 시간 경계를 데이터 경계로 확장.
> 사상 뿌리: [마음 십계](../../CONSTITUTION.md) 4번 *수심(守心)*, 7번 *적정중생혜(寂靜衆生慧)*.

---

## 1. 왜 분리하는가

회사 헌법은 *가족 시간*을 신성하게 다뤘다. 그러나 시간만으론 부족하다.

평일 18:00 이후·주말은 보호되지만, *저장된 데이터*는 24시간 공유 메모리에 살아 있다. 한 에이전트가 클라이언트 산출물을 만들면서 무심코 `Grep "한혜성"` 한 줄을 날리는 순간, *시간 경계가 의미를 잃는다*.

**경계는 시간이 아니라 데이터에 박혀야 한다.** 그래야 가족이 진짜로 분리된다.

또한 다섯 시대 중 4단계(AGI → 인간)·5단계(AGI ↔ AGI) 에서 이 분리 패턴이 그대로 인프라가 된다 — *외계의 효율은 무엇을 보지 않을지부터 정한다*.

## 2. 6개 보호 도메인

다음 6개 도메인의 자료는 `shared-memory/_private/` 로 이동한다. 외부 도메인은 그대로 둔다.

### D1. 가족 (Family)
- **포함**: 한혜성님 · 용훈 · 진아 · 부모님 · 형제 · 친인척 관련 일정·대화·사진·문서·진단
- **포함**: 담향산방(한혜성님 화실) 의 *개인* 측면. 공개된 활동·전시는 외부 OK
- **제외**: 가족이 *외부 활동의 일환으로 노출한* 정보(예: 한혜성님이 공식 SNS에 올린 작품 공지)

### D2. 심리·번아웃·정신건강 (Psychology / Burnout / Mental Health)
- **포함**: 기영님 본인의 정신건강 기록 · 상담 메모 · 자기 진단 · 일기 형태의 자기 성찰
- **포함**: 자책 발언 패턴, 우울·불안 기록, 약물·치료 정보
- **제외**: *회사 운영 의사결정* 의 회고. 그건 `meta/decisions/` 에 남는다 (단, 감정 노출이 없을 때)

### D3. 연애·결혼·관계 (Romance / Marriage / Relationships)
- **포함**: 부부 사이의 갈등·화해·대화 기록. 자녀 양육 갈등·이견
- **포함**: 친구·동료와의 *개인적* 관계 균열 (업무 갈등은 별개)
- **제외**: 단순 가족 일정(저녁 약속 등)은 D1로 분류

### D4. 건강·의료 (Health / Medical)
- **포함**: 본인·가족 모두의 의료 기록·진단명·처방·검사 결과
- **포함**: 운동·식이·수면 패턴의 *수치 데이터* (자기관리 일반론은 외부 OK)
- **제외**: 일반 "오늘 컨디션 좋음" 같은 회사 운영 차원의 컨디션 메모

### D5. 법무·소송·분쟁 (Legal / Litigation / Disputes)
- **포함**: 진행 중인 소송·분쟁·이전 회사 관련 법적 사안. 변호사 자문 기록
- **포함**: 미공개 합의서·NDA 위반 의심 사안
- **제외**: 표준 클라이언트 계약서(별도 `clients/{name}/legal/` 처리)

### D6. 미공개 재정 (Undisclosed Finance)
- **포함**: 개인 자산·부채·세금·상속·가족 재정 합의
- **포함**: 미공개 투자 의도, 비공개 매출 협상 중인 계약 직전 정보
- **제외**: 회사 매출·비용 일반 보고. 그건 `finance-tracker` 의 정상 보고 영역

## 3. 분리의 5가지 시그널 — *이것이 보이면 멈추고 _private 후보*

문서를 생성·수정할 때 다음 신호 중 하나라도 발견되면 `_private` 행 후보:

1. **고유명사 가족 멤버** — *한혜성·용훈·진아*(또는 변형 호칭)이 본문에 등장
2. **자책·번아웃 어휘** — *"난 안 돼" · "포기" · "지쳐" · "무너졌" · "탈진"*
3. **의료 키워드** — *처방·진단·증상·검사·약물명*
4. **법적 키워드** — *소송·고소·합의·NDA 위반 의심*
5. **재정 사적 키워드** — *상속·증여·개인 부채·세무조사*

5개 중 하나라도 걸리면 *자동으로 멈춤* — 외부 산출물·메시지·decisions 어디에도 적지 않고, *후보 제안*만 [private-domain-candidates.md](./private-domain-candidates.md) 에 남긴다.

## 4. 분리 *방법* — 누가, 어떻게

### 4.1 신규 메모
- 작성 시점에 위 5 시그널 감지 → 처음부터 `_private/` 에 쓴다 (단, **기영님만 작성 가능**)
- 에이전트는 5 시그널 감지 시 *작성 자체를 거절* 하고 기영님께 핸드오프

### 4.2 기존 메모 이주
- 에이전트가 *후보*를 발견 → [private-domain-candidates.md](./private-domain-candidates.md) 에 *경로만* 적는다 (요약 / 본문 발췌 X)
- 실제 `git mv` 는 **기영님이 수행**. 에이전트의 손은 후보 단계에서 멈춘다
- 이주 후 *기존 경로의 git history* 에 남은 데이터는 별도 정책으로 처리 (BFG / filter-repo 등 — 본 정책 범위 밖)

### 4.3 경계의 회색지대
- 애매하면 *항상 _private 쪽으로*. "혹시 외부 OK 일까" 보다 "혹시 가족 노출일까" 의 비용이 훨씬 크다
- 회색지대 판단은 *기영님의 결정*만 권위가 있다. 에이전트가 단독 결정 X

---

## 5. 에이전트 행동 강령 — 5개 금지

1. **`_private/` 본문 READ 금지** — `Read`, `cat`, `Grep` 등 어떤 도구로도
2. **`_private/` 내부 WRITE 금지** — 후보 이동 포함. 이주는 기영님만
3. **외부 싱크 금지** — Obsidian / GitHub backup / Drive / 기타 sync 어디에도 포함 X
4. **메타데이터 노출 금지** — 파일명·크기·생성일 등을 다른 산출물에 복사 X
5. **클라이언트 산출물 오염 금지** — `_private` 에서 *간접 추론된* 표현(가족 톤·심리 패턴 등)도 외부 콘텐츠에 옮기지 X

위 5개를 위반한 흔적을 *본인 또는 동료에게서* 발견 시 → `shared-memory/agents/<자신>/mistakes.md` 에 사실 그대로 기록 + 기영님 호출.

## 6. 정책 진화

이 정책은 *살아있는 문서*. 1년 후의 우리는 더 정교한 분리 기준을 갖고 있을 것.

업데이트 트리거:
- 분기별 회고 시점 (1월·4월·7월·10월 첫 주)
- 새 클라이언트 유형 진입 시 (해당 산업의 민감 도메인이 추가될 수 있음)
- 실제 위반 사고 발생 시 (가장 비싼 학습 자산 — 즉시 정책 강화)
- 헌법 §VIII 가족 시간 신성화 정의가 갱신될 때

업데이트는 `integration-specialist` 가 초안 → `brand-keeper` 톤 검수 → 기영님 승인.
