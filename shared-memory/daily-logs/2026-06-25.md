## 교훈

1. **"이동" 의 시맨틱은 도구마다 다르다.** Docker Desktop 의 Disk image location 은 *"앞으로 여기 쓸 거야"* 이지 *"옛 짐 옮긴다"* 가 아니다. 변경 전 변경 후 *명시적 검증* (docker images / 옛 자리 잔존) 이 표준.
2. **자정 넘은 시간 + 복구 길 4개 중 헷갈리면 — 클라이언트 0명 시점은 깨끗 재시작이 항상 최선.** 손실 비용 0, 회수 깨끗.
3. **brain180 같은 흔한 이름은 와일드카드 매치에 함정.** `.gemini/history/brain180` 같은 *우연한 이름 충돌* 이 잡힘. 위치 후보 명시 + 와일드카드는 fallback 으로만.
