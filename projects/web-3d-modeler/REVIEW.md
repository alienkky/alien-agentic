# REVIEW — 웹 3D 모델러 설계 전체 검토

> 검토자: master-orchestrator · 2026-06-14 · 대상: PLAN/PROMPT/WORKFLOW v1 → v2
> 트리거: 기영님 3대 결정 (① AA 자체 IP ② 전체 검토 ③ iPad→갤탭→폴드6 멀티디바이스)

---

## 0. 한 줄 결론

설계 v1 은 **기술 골격(B-rep 커널 + 워커 + 픽킹)은 견고**했으나, **두 개의 큰 구멍**이 있었다 —
(A) "본진이 어디인가"를 데스크톱처럼 암묵 가정했고, (B) 자체 IP로서의 협업/사업 레이어를 "옵션"으로
밀어뒀다. 기영님 결정으로 둘 다 메꿨고, 그 결과 **입력·디바이스 토대가 Phase 6 → Phase 0 으로 승격**
됐다. 이게 이번 검토의 가장 중요한 변경이다.

---

## 1. 검토 방식 — 5개 렌즈

설계를 다음 5개 렌즈로 훑었다:

1. **기술 타당성** — OCCT WASM + Three.js 스택이 실제로 목표를 받치는가
2. **순서 타당성** — 페이즈 의존성이 맞물려 있는가 (앞이 뒤를 막지 않는가)
3. **본진 정합** — 타깃 디바이스/사용자와 설계가 일치하는가
4. **리스크 정직성** — 진짜 위험을 숨기지 않았는가
5. **AA DNA 정합** — 자체 IP·메모리 축적·십계와 어긋나지 않는가

## 3. 검토에서 "유지"로 판단한 것 (바꾸지 않음)

견고해서 그대로 둔 결정들 — 검토는 "다 뜯어고치기"가 아니다:

- **OCCT.js B-rep 커널** — 브라우저에서 진짜 CAD 를 하는 유일한 현실적 길. 대안(메시 전용 Manifold)은
  스케치·필렛·STEP I/O 를 못 한다. **유지.**
- **커널을 Web Worker 에 격리** — UI 블로킹 방지의 정석. **유지.**
- **테셀레이션 토폴로지 ID 규약** — 픽킹·편집의 척추. WORKFLOW §4 포맷 견고. **유지.**
- **문서 = 피처 트리 JSON** — B-rep 을 파생물로 두는 설계. 저장·undo·재평가가 깔끔. **유지.**
- **direct-first, history-light** — Shapr3D 의 본질 정확히 포착. 풀 히스토리 욕심은 자멸. **유지.**
- **수직 슬라이스 + tsc 게이트** — multica 교훈 계승. **유지.**

## 5. 남은 열린 질문 (Phase 0 진입 전 확인하면 좋음)

> 막지는 않는다 — 합리적 기본값으로 진행 가능. 다만 기영님이 일찍 답하면 재작업이 준다.

1. **네이밍.** 코드명 Nebula 를 정식 제품명으로 갈지, 별도 브랜드명을 지을지. (기본: Nebula 유지)
2. **오프라인/PWA.** 설치 없이가 핵심이나, 태블릿에선 PWA(오프라인·홈 추가)가 강력. Phase 5에 포함할지.
   (기본: Phase 5 저장 단계에서 PWA 매니페스트까지)
3. **사업 모델 시점.** Phase 7 구독을 언제 구체화할지 — MVP 검증 후로 미룸이 기본. (기본: Phase 6 이후)
