# [Feature Request] 워크스페이스 사용량 대시보드에 제공자(Provider) 분리 표시

- **작성일**: 2026-05-17
- **작성자**: Alien Agentic (kky710@gmail.com / Alien Kim)
- **대상**: Multica 플랫폼 팀
- **트래킹 이슈**: ALI-23 (alien-agentic 워크스페이스)
- **우선순위 제안**: Medium — 운영 의사결정에 영향

---

## 요청

워크스페이스 **사용량(Usage)** 페이지의 비용·토큰·태스크 집계를 **제공자(Claude / Codex 등) 단위로 분리**해서 볼 수 있게 해주세요.

## 현재 동작

- **상단 KPI 카드 4개** (비용 / 토큰 / 실행 시간 / 태스크) — 총합만 노출
- **일별 토큰 차트** — 제공자 구분 없는 스택
- **리더보드** — 에이전트별로 토큰/비용/시간/태스크를 보여주지만, 한 에이전트가 Claude와 Codex 둘 다 사용한 경우 **어느 제공자에서 얼마를 썼는지 알 수 없음**

(현재 대시보드 스크린샷은 별도 첨부 — 이슈 ALI-23 의 코멘트에 포함되어 있음)

## 원하는 동작

| # | 변경 위치 | 변경 내용 |
|---|---|---|
| 1 | **KPI 카드** | 비용·토큰 카드에 "Claude $X / Codex $Y" 동시 표시 (서브라인) 또는 카드 자체를 제공자별 복제 |
| 2 | **일별 토큰 차트** | 제공자별 색상으로 스택 분리 (현재는 단일 시리즈) |
| 3 | **리더보드 컬럼** | 토큰 컬럼을 "Claude / Codex"로 쪼개거나, 행 클릭 시 제공자별 breakdown drawer 노출 |
| 4 | **상단 필터** | 7d/30d/90d 옆에 "전체 / Claude / Codex" 토글 추가 |

## Why (비즈니스 이유)

- **한도 관리** — Claude Max와 ChatGPT Pro/Codex 두 구독의 한도 소진 속도를 따로 추적해야 어느 쪽이 먼저 위험한지 알 수 있음. 현재는 합산되어 보여 한도 임계 도달 시점 예측이 어려움.
- **라우팅 최적화** — "어떤 작업을 어느 모델에 보낼지"의 의사결정 근거가 필요. 제공자별 비용/시간/태스크 효율을 비교할 수 있어야 라우팅 규칙을 조정 가능.
- **월말 정산** — 내부 비용 배분(클라이언트 작업 vs 자체 R&D)에서 제공자별 분리는 회계 항목 분리에 필수.

## 데이터 가용성

각 태스크 실행 레코드에 *어떤 CLI/모델이 호출되었는지* 이미 메타데이터로 들어있을 것으로 추정 (CLI 라우팅 시점에 결정되는 값). 새 컬럼 추가 없이 **기존 데이터의 그룹핑·시각화 변경만으로 충분**할 가능성이 높습니다.

만약 현재 실행 레코드에 provider 필드가 없다면, 그 부분이 먼저 작업되어야 합니다 — 그쪽 일정도 알려주시면 감사하겠습니다.

## 수용 기준 (Acceptance Criteria)

- [ ] 사용량 페이지 진입 시 기본 뷰에서 Claude/Codex 분리가 한눈에 보인다
- [ ] 30일/90일 등 기간 전환에도 분리 표시 유지
- [ ] 데이터가 한쪽 제공자만 있어도 깨지지 않음 (빈 시리즈 처리)
- [ ] 모바일 뷰포트에서도 분리 정보가 합쳐지지 않고 스크롤로 접근 가능
